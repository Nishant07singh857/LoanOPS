# Task 4 — Agent Portal Build

## Summary

Built the **complete AGENT PORTAL** for the Loan Ops Platform — 14 pages (11 top-level + 1 dynamic candidate detail + 1 shared layout + the agent nav module). Every agent page is wrapped by the shared `agent/layout.tsx` with `PortalLayout` in **topbottom** nav mode (top bar + bottom nav, mobile-first, no sidebar), `SessionProvider`, and `PageTransition`. Lint passes with **zero errors and zero warnings**, all 14 agent routes return HTTP 200 with no compile errors in `dev.log`. Money is in paise and formatted via the shared `formatPaiseToINR` / `formatPaiseToINRShort` helpers. WhatsApp buttons actually call `openWhatsApp` with `buildWhatsAppMessage` from the shared `whatsapp.ts` module — using real candidate mobile numbers from `agentCandidates`. No indigo/blue colors used; the emerald/teal/info fintech theme is preserved throughout, and the agent portal uses `bg-info` as its brand accent (per spec).

## Design Standards Met
- ✅ All pages use `PortalLayout` via the shared agent layout (no repetition)
- ✅ All KPI displays use `KPICard` with proper variants and sparkline arrays
- ✅ All statuses use `StatusBadge` with raw status strings (variants match enum strings — ACTIVE/PENDING_DISBURSEMENT/PENDING_VERIFICATION/RECORDED/VERIFIED/ALLOCATED/REJECTED/FULFILLED/BROKEN/CANCELLED/OPEN/IN_REVIEW/RESOLVED/CLOSED/ASSIGNED/UPCOMING/DUE/OVERDUE/PAID/PARTIALLY_PAID + priority variants URGENT/HIGH/MEDIUM/LOW + AI_HIGH/AI_MEDIUM/AI_LOW for reasons)
- ✅ Money formatted with `formatPaiseToINR` (full) and `formatPaiseToINRShort` (KPIs); interest rates with `formatBpsToPercent` where applicable
- ✅ All tables responsive — `<table>` hidden on mobile, card list shown on mobile (Schedule + Payments in candidate detail, Cash Collections list)
- ✅ All modals/dialogs use shadcn `Dialog` (Record Cash / New PTP / Escalate / New Task / Schedule Follow-up / Resolve / Use Template / Broadcast / New Ticket)
- ✅ `toast` from sonner used everywhere for action feedback
- ✅ Framer Motion entrance animations on cards/lists (`FadeIn`, `StaggerContainer`+`StaggerItem`)
- ✅ Each page top-level wrapped in `PageTransition` (via agent layout)
- ✅ NO indigo/blue colors — only `bg-primary` (emerald), `text-info` (teal), success/warning/destructive variants
- ✅ Premium fintech aesthetic — `rounded-2xl`, `shadow-premium`, `shadow-glow`, gradient accents on welcome banner, KPI cards with sparklines
- ✅ Mobile-first — `topbottom` nav mode shows top bar + bottom nav (no sidebar), with `min-h-[44px]` touch targets, sticky bottom action bar on candidate detail (mobile-only via `sm:hidden`), `pb-24 sm:pb-6` on candidate page to clear bottom bar
- ✅ WhatsApp buttons actually call `openWhatsApp(phone, msg)` with `buildWhatsAppMessage(template, ctx)` using real mobile numbers from `agentCandidates`
- ✅ Hover states + smooth transitions on all interactive elements
- ✅ `SectionHeading` used on every page with title + description + (where applicable) action button
- ✅ All money math uses paise values directly — never `Number()`/`parseInt()`/`parseFloat()` for authoritative money (only the conventional `/100` for display conversion to rupees when building WhatsApp message strings, consistent with the existing admin loan detail page pattern)
